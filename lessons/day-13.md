# Day 13｜五案例驗收＋導入前後比較

Phase 5 · 約 45～60 分鐘 · [總路線](../ROADMAP.md) · [今日文章](../articles/day-13.md)

## 先懂這兩件相連的事（10～15 分鐘）

**用五個案例檢查結果與路徑**

Agent 的驗證要同時看回答內容與執行過程。統計適合確定性斷言，生成文案則檢查有沒有改數字、編造或超出範圍。

**比較導入前後，說清楚值得與代價**

改造需要能回答「這有什麼幫助」。流程圖與 trace 可能改善理解與維護，但框架也增加依賴、事件處理與學習成本，不能直接宣稱更快更便宜。

## 用咖啡 Bot 想一遍

五次驗收都通過，是否就能說模型準確率是 100%？說明這份驗收能支持的範圍。

先自己回答兩三句，再動手驗證；答不出來可回看[概念速查](../docs/concepts.md)，不用讀完整份官方文件。

## 動手做（25～30 分鐘）

1. 跑 demo 表五個案例：正常、零筆、模型失敗、跨使用者、模糊期間，填入實際結果與路徑。
2. 以同一份 fixture 比較原 handler 與新 graph 的統計與組織方式。
3. 填 talk 比較表：一項可觀察的幫助、一項成本；沒有量測的速度或費用就保留未量測。
