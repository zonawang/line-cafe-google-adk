# Day 11｜LINE＋身分隔離：只接一個護照入口

Phase 5 · 約 45～60 分鐘 · [總路線](../ROADMAP.md) · [今日文章](../articles/day-11.md)

## 先懂這兩件相連的事（10～15 分鐘）

**把 workflow 接回 LINE 的邊界**

LINE webhook 負責驗證、辨識發話者與選擇 handler；workflow 負責護照處理。回覆轉成 LINE 訊息是另一個邊界。

**個人化之前，先確定是誰的資料**

使用者與聊天室來源要由 LINE 驗證後的 event 決定。模型輸出的 userId、聊天文字裡的名稱，都不能直接當作讀取權限。

## 用咖啡 Bot 想一遍

模型回傳另一個 userId 時，哪一層應阻止資料來源被切換？

先自己回答兩三句，再動手驗證；答不出來可回看[概念速查](../docs/concepts.md)，不用讀完整份官方文件。

## 動手做（25～30 分鐘）

1. 在新應用目錄依 handlePassportText 接入「本月咖啡護照」，把已驗證 actorId 傳入 workflow／adapter。
2. 先用模擬 LINE event，將輸出交給既有訊息組裝；有餘裕再測實機 channel。
3. 用 A、B 不同造訪數測試，A 要求 B 的護照時只讀 A 或拒絕；確認群組 ID 與個人 ID 沒混用。
