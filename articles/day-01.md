# 咖啡 Bot 做完之後，我想帶著原本的專案認識 Google ADK

前一個系列，我和 Codex 一路替 LINE Cafe Bot 加上找咖啡廳、收藏、偏好記憶、安排時間、群組投票和咖啡護照。

從「今天想去哪裡喝咖啡」，到選好店、約好時間，再把喝完之後的感受記下來，這隻 Bot 已經累積了一段完整的旅程。

寫完咖啡護照那一篇時，我也替這段功能開發收了尾。

不過，做好的專案還可以繼續陪我學新東西。

**今天開始，我想帶著這些原有的專案，認識一個對我來說全新的工具：Google ADK。**

我也是第一次接觸它。看到 agent、tool、workflow 這些名詞時，最想先弄懂的其實是一個很基本的問題：

> 我的咖啡 Bot 已經會呼叫 Gemini，也能讀資料、做推薦。那 Google ADK 會放在哪裡，又能幫我做什麼？

接下來，我打算用十五天，每天理解一點、實作一點，再把學到的內容寫下來。先從自己熟悉的咖啡 Bot 出發，應該比較容易看懂新工具和原本程式之間的關係。

## 先把 Google ADK 放回我熟悉的咖啡 Bot

Google ADK 的全名是 **Agent Development Kit**，是 Google 提供、用來開發 AI agent 應用的框架。它提供組織 agent、使用工具與安排執行流程等能力。[官方介紹](https://adk.dev/)

這樣說還是有點抽象，所以我先拿原本的咖啡護照來對照。

使用者在 LINE 輸入：

```text
本月咖啡護照
```

畫面最後會出現造訪次數、不同店家、平均評分，以及一小段 Gemini 寫的回顧。但在卡片出現以前，程式其實已經做了好幾件事：

```text
收到 LINE 指令，確認是哪位使用者
                ↓
讀取這個人的咖啡足跡與想去清單
                ↓
計算本月造訪次數、店家數與平均分數
                ↓
把統計交給 Gemini，整理成兩句回顧
                ↓
組成 LINE 卡片並回覆
```

把它拆開來看，我就比較能分清楚每個工具的工作。

LINE 負責接收訊息與顯示結果；Firestore 保存足跡與收藏；程式負責統計；Gemini 負責把資料整理成自然的文字。

而我接下來想用 ADK 練習的，就是中間這段工作的組織方式：哪些步驟先執行、資料怎麼交給下一步，以及遇到不同情況時要怎麼繼續。

## 第一個要認識的概念，叫做 graph workflow

先把 graph 想成一張有節點、有連線的流程圖就好。

一個節點做一件事，連線則告訴我們這些工作之間的關係。放進咖啡護照裡，可以先縮成三步：

```text
讀取紀錄 → 計算統計 → 產生回顧
```

統計需要先拿到紀錄，回顧又需要先知道統計結果，所以這三步有明確的先後順序。

如果再加一個情況：這個月完全沒有紀錄呢？

```text
讀取紀錄
    ↓
計算統計
    ↓
有沒有完成的造訪？
   ↙          ↘
 有            沒有
 ↓              ↓
產生回顧     提示先記下第一次造訪
```

這時候，流程就有了分支。沒有資料時，可以直接給使用者一個清楚的下一步。

ADK 的 graph workflow 能讓我們把這些步驟與關係定義在程式裡，再由框架推進執行。節點可以包含一般函式、工具或 AI agent。[官方 graph workflow 說明](https://adk.dev/graphs/)

## 算平均分數這件事，我還是想交給原本的程式

畫出流程後，有一個分工也跟著變清楚了：哪些地方需要 AI，哪些地方已經有明確規則。

例如同一家咖啡廳去了三次，應該算三次造訪、一家店；三筆評分是 5、4、3，平均就是 4 分。這些規則在原本的咖啡護照裡已經寫好了。

因此接下來改造時，我會先保留這些統計，再把結果交給 Gemini 寫回顧。

這也延續了上一篇咖啡護照的分工：

```text
程式：把次數、店家與評分算清楚
Gemini：根據這些資料，寫出兩句自然的回顧
ADK：組織這些步驟，讓資料沿著流程往下走
```

對我來說，這個例子比一次記住所有類別名稱更有幫助。先知道每一段為什麼存在，再去看它用什麼 API 表達，會比較有方向。

## 原本就做得到，為什麼還想試 ADK？

回頭看原本的程式，護照的 handler 已經會依序讀資料、算統計、產生摘要，再組成訊息。這條流程用一般函式也能寫得很清楚。

所以我想帶著一個問題開始這次練習：

> 同一個功能，換成 ADK 來組織後，我會更容易看懂流程、找到問題，或加入下一個步驟嗎？

這需要真的做過，再拿前後兩個版本比較。框架會增加新的概念與依賴，值不值得，要看它對這個專案帶來什麼具體幫助。

也因為這樣，第一條主線就選「本月咖啡護照」。範圍小，資料、統計和摘要的責任又已經分開，適合一段一段接進來，也方便檢查結果有沒有改變。

## 今天先從一張圖開始，下一步再讓 agent 跑起來

今天先把整個角色分工與護照流程整理清楚。Repo 裡也準備了一個離線小練習，用三個一般 JavaScript 函式，模擬讀取紀錄、計算統計與顯示固定文案。

它使用虛構資料，還沒有呼叫 ADK 或 Gemini，目的是先看懂資料怎麼從一步走到下一步。

後面才會逐步建立第一個 agent、加入工具，再把原本的護照流程接成 ADK workflow。目前還在起步，完整的 ADK 與 LINE 整合會隨著每天的實作慢慢補上。

之前做咖啡 Bot 時，每一篇文章都讓它多學會一件事。這次，我想讓已經做好的 Bot 當我的教材，陪我把 Google ADK 一點一點弄懂。

下一篇，就從第一個能跑起來的 agent 開始。
