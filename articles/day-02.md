# 先挑一條小流程，再建立第一個 Google ADK agent

> Day 02 · 15 天版概念短文草稿 · [今日實作](../lessons/day-02.md)
> 狀態：待實作與個人編輯。下方是概念文字；完成後補入自己的結果再發布。

同時搬移搜尋、群組、提醒與多模態，會很難辨認學到的是 ADK 還是周邊服務。咖啡護照提供一個小而完整的切面：資料先變成可信統計，再交給 AI 寫短文。這條切面也方便保留原本的統計作為比較基準。

Agent 的入門配置可以從三個欄位理解：名稱用來辨識角色，模型提供理解與生成能力，instruction 描述任務與限制。先完成單一任務，之後新增工具時，比較容易觀察行為改變的原因。

## 今天的咖啡 Bot 情境

這個 agent 回答了「你去了 5 次」時，問題出在模型不夠強，還是任務與資料邊界沒寫清楚？
