# 除了答案，我還要看見 agent 做過的步驟

> Day 05 · 第一人稱學習紀錄草稿 · [今日實作](../lessons/day-05.md)
> 實作尚待完成；本文以計畫語氣撰寫，做完後再補入真實結果。

看見 agent 回了一句正確的話之後，我還想再多看一點：它中間到底做了什麼？

咖啡護照的次數如果剛好答對，只看最後文字，還不能確認它有沒有真的查工具。因此今天把焦點放到一次執行的過程。

Runner 負責驅動 agent 或 workflow。過程中出現的工具呼叫、工具結果和回覆，可以透過 event 留下可觀察的線索。

我打算把一次請求整理成四步：使用者問了什麼、選了哪個工具、工具回傳什麼，以及最後怎麼回答。哪一步開始和預期不同，就從那裡往回找。

這一天也先留一點時間整理前面的理解。能拿同一份紀錄解釋模型、agent 和工具的分工，後面開始拆 graph 時就比較不容易迷路。
