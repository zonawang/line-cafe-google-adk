# 三分鐘 demo 與五個驗收案例

以下是目標驗收表，初始狀態全部未執行。Day 10 先做前三個，Day 13 完成五個。這份人工驗收表不採用 ADK Python evalset 格式，避免在 TypeScript 入門時多學一套工具。

## Demo 順序

1. **0:00～0:30**：展示「本月咖啡護照」與節點圖，說明 fixture 或真實測試資料。
2. **0:30～1:20**：跑正常案例，對照統計 JSON、模型短文與執行事件。
3. **1:20～2:00**：切成零筆，說明程式分支與空狀態。
4. **2:00～2:40**：模擬模型故障，展示固定摘要與統計仍可用。
5. **2:40～3:00**：用一句話交代尚未完成的整合與下一步。

## 統計與生成分開檢查

統計可以做固定值斷言，包含零筆與日期範圍。生成文案檢查數字能否追溯、不猜偏好與金額、長度是否合適。Trace 檢查必要步驟與不該發生的呼叫。模型句子不必逐字一致。
