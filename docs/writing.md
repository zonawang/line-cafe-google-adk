# 每天十分鐘寫一篇短文

每天一個主題、約 200～400 字就好。文章先服務「把今天學懂的東西說清楚」，到月底再選幾篇整成完整主文。Day 1 已有完整概念文，Day 2～30 各有不同概念草稿與實作紀錄欄位。

## 每篇只填四件事

1. 一個具體問題：例如，沒有紀錄時是否還需要叫模型？
2. 今天的一個理解：例如，零筆分支可以由程式決定。
3. 一個真實證據：一張圖、一段輸出或一個 commit。
4. 一句下一步：例如，明天試著把資料來源換成 adapter。

寫三句也可以。還沒做完就寫「今天先畫好流程，串接待續」，不要把預期輸出寫成已完成紀錄。使用 fixture 或示意圖需直接註明，截圖先移除憑證與個人識別資訊。

## 月底主文的建議題目

**我用既有 LINE 咖啡 Bot 學 Google ADK：從一張流程圖，到可以解釋的 agent workflow**

建議串起 Day 1（問題與流程）、Day 6（工具）、Day 11（graph）、Day 18～19（摘要與降級）、Day 26（比較與取捨）。保留自己踩到的一個坑，刪掉重複名詞定義。

## 發布前快速檢查

- [ ] 每個「我做了」都有實際證據。
- [ ] 一般函式、ADK 能力與產品設計的責任說清楚。
- [ ] 提到版本、資料來源與目前限制。
- [ ] 沒有把五個驗收案例說成整體準確率。
- [ ] 官方來源連結放在對應概念附近。
