# 每天十分鐘寫一篇短文

每天一個主題、約 300～500 字就好。文章先服務「把今天學懂的東西說清楚」，到 Day 15 再選幾篇整成完整主文。Day 1 已有完整概念文，Day 2～15 各有不同概念草稿與實作紀錄欄位。

## 延續原本 Cafe Bot 系列的口吻

以第一人稱寫學習與實作紀錄。先接續前一篇留下的功能或問題，再說明「今天想讓哪一件事變清楚」，從咖啡 Bot 的具體情境帶出一到兩個名詞。

開場可沿用這個方向：前面已完成找店、收藏、行程與護照，今天開始帶著原本的專案認識 Google ADK。作者也是第一次接觸，以正在理解的語氣寫清楚選擇與疑問。

用短段落、自然的轉折、少量對話與簡單資料流說明；名詞出現時立刻接一個 Cafe Bot 例子。分享自己為何挑這個小範圍、原本規則要保留什麼，以及下一篇要繼續確認什麼。Day 1 作為系列開場可以比每日短文長，其餘先維持 300～500 字，再補實作紀錄。

原有風格可參考 [咖啡護照文章](https://github.com/zonawang/line-cafe-passport/blob/main/medium.md)、[Rich Menu 文章](https://github.com/zonawang/line-cafe-rich-menu/blob/main/medium.md)、[偏好記憶文章](https://github.com/zonawang/line-cafe-companion/blob/main/medium.md)。參考敘事節奏與技術解釋方式；本次的錯誤、測試與成果以自己的實際紀錄為準。

草稿中的「想做、打算、接下來會確認」保留為計畫語氣。不要編造踩坑、對話、手機實測或已部署情節。實作後再補真實結果，收尾接到下一個問題。

## 文章要能直接複製到 Medium

正文使用簡單標題、短段落、粗體、引言與少量條列。移除待填欄位、編輯提示與給協作 AI 的指令；指令可放在句子中，短結果用引言呈現。流程優先用一句箭頭順序與條列解釋，不讓文章依賴 Mermaid、Markdown 表格或 ASCII 圖才能讀懂。

所有參考連結使用完整 HTTPS 網址，不能保留 GitHub 相對路徑。已完成的內容依最新 learning-log.md 和使用者確認改為實作紀錄；尚未接上的服務保留未完成狀態。Day 1 已完成離線練習與角色圖，不能寫成 ADK、Gemini 或 LINE 的整合已完成。

交付時提供完整可複製正文，與 repo 保存相同內容；寫作說明放在正文之外。

## 每篇只填四件事

1. 一個具體問題：例如，沒有紀錄時是否還需要叫模型？
2. 今天的一個理解：例如，零筆分支可以由程式決定。
3. 一個真實證據：一張圖、一段輸出或一個 commit。
4. 一句下一步：例如，明天試著把資料來源換成 adapter。

寫三句也可以。還沒做完就寫「今天先畫好流程，串接待續」，不要把預期輸出寫成已完成紀錄。使用 fixture 或示意圖需直接註明，截圖先移除憑證與個人識別資訊。

## 最後整合主文的建議題目

**我用既有 LINE 咖啡 Bot 學 Google ADK：從一張流程圖，到可以解釋的 agent workflow**

建議串起 Day 1（問題與流程）、Day 3（工具）、Day 6（graph）、Day 9～10（摘要與降級）、Day 13（比較與取捨）。保留自己踩到的一個坑，刪掉重複名詞定義。

可複製 [文章模板](../templates/article.md) 或直接改當日草稿。文章目前只存於 GitHub；公開到部落格可以在自己完成編輯後再做。

既有文章中的實作截圖與流程圖要保留。Medium 版可直接嵌入原始圖片並加上簡短圖說；若流程原本用 Mermaid 表示，另提供圖片版本。整理成可複製格式時，不要省略圖片或只留下學習紀錄的連結。
